1. Collapse four CardData rule-keeper modules into one validator

Strong in-process
src/utils/cardIO.ts:65-78  ·  src/utils/cardParser.ts:103-127  ·  src/services/llm/adapters/base.ts:145-155  ·  src/services/FileService.ts:179-222
Before · 4 modules, 4 rule-keepers

Three boolean validators + one duplicated parse copy, all maintaining "what is CardData".

After · 1 validator, 4 callers

One module, one rule set. parseCardFromCode signature upgrades to CardData.

Problem

Four modules independently maintain "what fields make a Card". Adding one field requires edits in all four. Two return boolean, one returns string[], the parse returns Partial<CardData> — drift is inevitable.

Solution

Extract src/card/cardValidation.ts as the single rule-keeper. Three callers cross the seam; FileService deletes its private parse copy.

  • ✓Locality: 1 place to fix
  • ✓Leverage: 4 callers · 1 module
  • ✓Delete 3 shallow wrappers
  • ✓Tests hit one interface
  • ✓Deletion test passes (pass-through)
  • ✓CardData, not Partial, everywhere

2. Replace window-globals with factory seam in stores & services

Strong ports & adapters
src/stores/useAIStore.ts:72, 129-134  ·  src/services/FileService.ts:39-54
Before · module-level globals

Parallel test files overwrite each other's globals; production never writes the default branch.

After · factory seam, 2 adapters

Two adapters (prod + in-memory test) justify the seam; each test owns its store instance.

Problem

(window as any).__adapterFactory and let api are module-level mutable globals. Tests pollute each other; TypeScript gives up; production never exercises the fallback path.

Solution

Zustand factory pattern: createAIStore({ factory }) + createFileService({ api }). Each test instantiates its own; prod wires at main.tsx boot.

  • ✓Seam: 2 adapters
  • ✓Test isolation restored
  • ✓Types return
  • ✓Locality: globals gone
  • ✓~30 LOC delta, big win
  • ✓Lives at external interface

3. Move connectError lifecycle into useNodeGraph

Worth exploring in-process
src/relic/RelicEditor.tsx:48-53, 80-84  ·  src/node-editor/useNodeGraph.ts:115-137
Before · editor owns error state, hook leaks semantics

Editor imports hook semantics, owns string error lifecycle, calls setError('连线失败：' + reason).

After · hook owns error, editor observes

Hook returns connectError: string | null + clearConnectError(). Editor = pure presentation.

Problem

Editor holds useState<string>('') for connect errors and manually calls setError because hook doesn't expose error state. Hook knows about flushSync semantics; editor mirrors them.

Solution

Hook owns connectError: string | null + clearConnectError(). Success path clears. Editor = useEffect observer.

  • ✓Editor -5 lines
  • ✓Error lifecycle in hook
  • ✓CardEditor reuses same pattern
  • ✓Locality: error rules co-located
  • ✓Test: hook tests the lifecycle
  • ✓CardEditor undo/redo unlocked

5. Inject kinds registry into graph validator

Speculative in-process
src/node-editor/graph.ts:355-366 (validateGraph per-kind)  ·  src/relic/kinds.ts (TRIGGER_KINDS, EFFECT_KINDS)
Before · validator knows strings, not registry

After · validator accepts options, callers inject registry

Problem

Validator checks data.event / data.kind are strings but not whether they're in the kinds registry. Bogus strings pass.

Solution

  • ✓Optional param — non-breaking
  • ✓graph.ts pure
  • ✓Catches bogus events pre-AI
  • ✓Locality: validation co-located
  • ✓AI JSON Schema path (v0.9) reuses
  • ✓Optional — schema unchanged
Top recommendation

Candidate 1 — Collapse the four CardData rule-keepers into one validator module

Four modules independently maintain "what fields make a Card". Adding one field requires edits in all four, with three different return shapes drifting independently. The deletion test is unambiguous: deleting any one concentrates complexity on the others — they're shallow pass-throughs. Extract src/card/cardValidation.ts as the single rule-keeper, upgrade parseCardFromCode to return CardData (not Partial<CardData>), and delete the three boolean wrappers. Locality win, leverage across four callers, tests concentrate on one interface — and it unblocks the v0.9 AI JSON Schema path which will need exactly this single source of truth.
