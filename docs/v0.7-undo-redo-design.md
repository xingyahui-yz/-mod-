# v0.7 撤销 / 重做设计

状态：设计冻结，v0.7-impl 已实施（2026-08-06）。Mac Cmd+Y 是实施时扩展（设计时未列出），详见 [v0.7-undo-redo-changelog.md](./v0.7-undo-redo-changelog.md)。
范围：Relic 节点图编辑器（`useNodeGraph` + `NodeGraphCanvas`）

## 决策

v0.7 采用 **history stack（不可变图快照）**，不采用 command pattern。

原因是当前 graph.ts 已经提供不可变纯函数：每个操作返回新 `NodeGraph`，无操作时返回原引用。快照可以直接复用这些函数和现有测试；command pattern 需要为每个操作维护逆操作、参数快照和失败回滚，尤其是删除节点（连同边）与导入 JSON，会把复杂度泄漏到 UI。快照的内存成本可控，且更适合当前单图、单用户、本地优先的 MVP。

## 模块与 seam

`graph.ts` 继续是纯函数模块，不知道历史；它只负责“给定图，计算下一张图”。

`useNodeGraph` 是历史模块的 seam，向编辑器暴露少量接口：

```ts
undo: () => void
redo: () => void
canUndo: boolean
canRedo: boolean
```

现有 `addNode / removeNode / moveNode / connect / disconnect / importJson` 都成为可记录的 mutation。调用方不需要知道栈结构，也不直接修改 graph。

## 状态模型

```ts
type HistoryState = {
  past: NodeGraph[]       // 最旧 → 最近一次提交前的图
  present: NodeGraph
  future: NodeGraph[]     // 最近一步可重做 → 最远一步
}
```

- 初始图只放在 `present`，`past` 与 `future` 为空。
- 成功 mutation 且返回引用不同：把旧 `present` 推入 `past`，新图成为 `present`，并清空 `future`。
- graph.ts 返回同引用表示 no-op；no-op 不产生历史记录，也不改变 `updatedAt`。
- `undo`：`present` 推入 `future`，取出 `past` 尾部作为 `present`。
- `redo`：`present` 推入 `past`，取出 `future` 尾部作为 `present`。
- 新 mutation 会清空 `future`，遵循编辑器常见的“分叉后重做失效”语义。
- 历史上限为 100 个 present 之前的快照；超出时丢弃最旧快照。该上限是实现常量，不进入 graph JSON。

## 操作语义

| 操作 | 可撤销 | 记录条件 |
|---|---:|---|
| 添加 / 删除节点 | 是 | 图引用变化 |
| 移动节点 | 是 | 位置实际变化 |
| 建立 / 删除连线 | 是 | 图引用变化；失败连线不记录 |
| 导入 JSON | 是 | `deserialize` 成功且图引用为新图 |
| 导出 JSON、生成代码 | 否 | 只读 |
| entityId/entityType 切换 | 否 | 视为新实体，清空历史并创建空图 |

删除节点的快照必须包含被级联删除的 edges，因此一次 undo 恢复节点及其边。`connect` 的失败结果仍返回给 UI，但不污染 history。

## UI

v0.7 在 `RelicEditor` toolbar 增加两个按钮：

- `撤销`：`disabled={!ng.canUndo}`
- `重做`：`disabled={!ng.canRedo}`

按钮旁显示快捷键提示。画布获得焦点时支持 `Ctrl/Cmd+Z` 与 `Ctrl/Cmd+Shift+Z`（Windows/Linux 的 `Ctrl+Y` 作为 redo 别名）。快捷键处理放在编辑器 seam，不放进 graph.ts；输入框正在编辑文本时不拦截浏览器原生撤销。

## 测试矩阵

1. 初始 `canUndo=false/canRedo=false`。
2. add → undo 恢复空图；redo 恢复节点。
3. move → undo 恢复旧坐标。
4. connect → undo 删除边；redo 恢复边。
5. remove（带边）→ undo 同时恢复节点和边。
6. 失败 connect、未知 node/edge 的 remove/move/disconnect 不增加 history。
7. undo 后新 add 清空 redo。
8. 连续两次 mutation 在同一 React batch 中按顺序形成两个历史步骤。
9. entityId 改变后图为空、旧图不可 undo/redo。
10. history 上限裁剪到 100。

## 分阶段实现

1. 在 `useNodeGraph` 内部提取一个小的 `commit(next)` helper，统一判断引用变化、推进 `past`、清空 `future`。
2. 将现有五类 mutation 接到 `commit`；保留现有返回值语义（特别是 `connect` 的 `{ok, reason}`）。
3. 添加 `undo/redo/canUndo/canRedo` 与 hook 测试。
4. 在 RelicEditor 接入 toolbar 与快捷键，并补一个端到端测试。
5. 最后 bump 到 `0.7.0`，完整运行 `npm test` 与 `tsc`。

## 非目标

- 不把历史写入 `.modstudio` 或 graph JSON。
- 不做跨实体全局历史；每个 `useNodeGraph` 实例拥有自己的历史。
- 不在 v0.7 引入持久化、协作合并或 command 序列化。
