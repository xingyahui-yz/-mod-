# v0.9 Card 端到端发布门禁

本清单对应 `docs/v0.9-card-node-editor-implementation-plan.md` 的完成定义。Card 的权威源数据是 `.modstudio/cards/`，`scripts/Cards/` 只保存显式生成产物。

## 自动化门禁

在仓库根目录执行：

```bash
npm test -- --run
npx tsc --noEmit
npx vite build
git diff --check
```

真实文件流由 `src/card/cardRelease.integration.test.ts` 覆盖：

- 保存 CardDocument → 重新加载
- 生成并记录 source/generator/artifact 指纹
- 外部修改被预检识别并阻止测试
- CardDocument 与 C# 一起移入 `.modstudio/trash/cards/`
- 恢复时重新检查活动 ID 冲突

## Electron smoke checklist

- [ ] 新建项目，创建 Card，确认 PascalCase ID；重复新建不会复用 ID。
- [ ] 编辑属性和行为图，等待“草稿已保存”，关闭并重新打开项目确认恢复。
- [ ] 点击“生成 C#”，确认 `scripts/Cards/<CardId>.cs` 写入且生成状态更新。
- [ ] 手工修改 C# 后重新生成，确认默认阻止；确认备份后才允许重生成。
- [ ] 删除 Card，确认文档和 C# 都进入 `.modstudio/trash/cards/`；恢复后 Card 与产物同时回归。
- [ ] 游戏测试先执行预检；缺失、过期、外部修改和未排除草稿不会调用启动 API。
- [ ] AI 为当前 Card 生成提案，确认属性/节点/连线差异后一次应用；编辑基线变化后提案变为只读且不能应用。
- [ ] 打开含损坏、未来 schema 或未知 kind 的项目时，左侧显示只读恢复项并可导出原始 JSON；回收站项可恢复。
- [ ] 点击“批量生成”后查看逐 Card 成功/跳过/失败报告，外部或未跟踪 C# 不会被静默覆盖。

旧 C# 反向解析只允许从显式 legacy-import 入口启动；正常项目打开不扫描 `scripts/Cards/`。
