# v0.9 Card 节点编辑器实施计划

> 状态：阶段 A-G 代码、自动化门禁和 Electron smoke 已完成；真实 provider/游戏行为按 v0.9 明确不在范围内
> 日期：2026-08-13  
> 决策依据：ADR-0002、ADR-0003、ADR-0005、ADR-0006  
> 实施方式：内部小提交持续可运行，用户侧完整后一次切换

## 1. 目标

原位升级现有 Card 编辑流程，使一张 Card 的基本属性与行为图由同一个模型、同一个 Store、同一个编辑器入口和同一份项目文档管理。

v0.9 完成后：

- `.modstudio/cards/<CardId>.json` 是 Card 的唯一权威项目源数据。
- `scripts/Cards/<CardId>.cs` 只是显式生成的产物。
- 正常加载绝不反向解析 C#；C# 解析器只能被一次性旧项目迁移入口调用。
- Card 表单与行为图共享撤销历史、自动保存、AI 提案和生成状态。
- Card 可包含多个不同触发根；每个触发根拥有一条独占、线性的效果链。
- v0.9 只交付 Card 的 Self/Owner 语义，不提前注册 Relic Any/EventTarget 能力。

## 2. 当前基线与实施约束

2026-08-13 的当前工作区基线：

- 323 项测试通过。
- TypeScript `--noEmit` 检查通过。
- Renderer、Electron main 与 preload 的 Vite 构建通过。
- 当前应用仍从 `scripts/Cards/*.cs` 正常加载 Card，并以数组索引选择 Card。
- 当前 Card 表单、NodeGraph 历史、AI 单次生成和游戏启动是彼此分离的路径。
- 工作区存在未提交的 Card 节点试作：包含第二份 CardData、第二个 CardEditor、平行 codegen/template，以及与最终决策冲突的 Card 级 `target`。

试作代码属于用户工作，实施时遵守以下约束：

1. 不整包提交，也不直接丢弃。
2. 可复用的 kind、模板、测试场景和 UI 代码逐项迁入权威模块。
3. 每项迁移后先由对应测试证明已经被吸收，再移除平行文件。
4. 任何提交结束时都不得新增第二个可达的 Card 编辑入口或第二份权威 Card 类型。

## 3. 提交纪律

每个提交必须：

- 只完成一个可解释的行为变化或基础能力。
- 同时包含对应测试；不提交“先破坏、下一步再修复”的中间态。
- 通过受影响测试、完整 TypeScript 检查和 Vite 构建。
- 不混入格式化、重命名或其他实体扩展。
- 完成替换时同步删除已失去消费者的旧路径。

提交信息建议使用 `test:`、`refactor:`、`feat:`、`fix:`、`docs:` 前缀。下面编号表达依赖顺序，不要求把所有提交放进一个 PR。

## 4. 小提交序列

### 阶段 A：锁定契约与单一模型

#### 01. `docs: lock v0.9 card editor decisions and rollout plan`

范围：提交领域词汇、ADR 修订和本实施计划，不改变运行时代码。

验证：文档链接有效；搜索确认“C# 正常加载”“第二套 Card”“Card 级 target”只出现在被拒绝方案或历史说明中。

#### 02. `refactor(kinds): enforce the v0.9 card registry boundary`

范围：

- 给 effect 注册定义增加固定 receiver 元数据。
- 只注册 v0.9 已支持的 Card trigger 和 Self/Owner effect。
- 移除依赖 kind 字符串后缀的 EventTarget 猜测规则。
- 结构校验拒绝当前 registry 不认识的 kind，并保留“未知数据进入只读恢复”的上层分类能力。
- 保持现有 Relic 行为不变，不暴露 v0.10 Any/EventTarget palette。

验证：registry 过滤、跨实体 trigger/effect、未知 kind 和 Relic 回归测试。

#### 03. `refactor(card): make the existing CardData the sole canonical model`

范围：

- 在现有权威 CardData 中加入不可变 `id`，统一默认 Card 工厂。
- ID 校验采用 PascalCase ASCII、英文字母开头、忽略大小写唯一。
- 更新现有编辑器、AI、校验、Store 和 codegen 的编译调用点。
- 不引入 Card 级 `target`；接收者只由 effect kind 表达。

验证：Card 外部数据 seam、默认值、ID 格式和所有旧调用点测试；编译证明仓库只消费这一份 CardData。

#### 04. `feat(card): define the versioned CardDocument envelope`

范围：定义当前 schema 的 CardDocument，原子聚合 Card、NodeGraph 与最近成功生成指纹；解析结果区分：当前可编辑、已知旧版待迁移、未来/未知只读、损坏不可加载。

验证：当前 schema round-trip、缺字段、未来 schema、未知 kind、原始 JSON 保真测试。

#### 05. `feat(card): add pure sequential CardDocument migrations`

范围：建立严格的 `vN → vN+1` 纯函数迁移链；迁移结果必须再次通过当前结构校验。此提交只处理内存转换，不写文件。

验证：逐版本升级、禁止跳级、迁移失败、输入不变性和幂等边界测试。

### 阶段 B：图约束与两级校验

#### 06. `refactor(graph): separate structural validation from card semantics`

范围：底层 NodeGraph 结构校验只负责类型、引用、端口、DAG 与 registry 契约；Card 生成语义由独立 validator 负责，草稿结构安全即可保存。

验证：结构损坏拒绝、空图/空 trigger 可作为草稿、未知 kind 被上层分类为只读。

#### 07. `feat(card): validate unique trigger roots and linear effect chains`

范围：Card 生成校验要求至少一个 trigger、同类 trigger 唯一、每个 trigger 至少一个 effect、effect 单入单出、每个 effect 只属于一个 trigger、无孤立节点、参数完整且 receiver 合法。

验证：每条规则一个正例和反例；错误结果定位具体 trigger、effect 或 edge。

#### 08. `feat(graph): prevent invalid card connections at edit time`

范围：在连线交互中提前拒绝第二条入边、第二条出边、跨分支共享和非法节点次序；底层生成校验仍作为导入/AI/磁盘数据的最终防线。

验证：连线错误不改图、不进入历史，并返回用户可理解的原因。

### 阶段 C：可靠文件边界与正常加载切换

#### 09. `feat(files): expose atomic file primitives through Electron`

范围：为文件端口增加原子替换、复制/移动、删除、存在性与目录读取所需的最小能力；主进程继续执行绝对路径与参数校验。

验证：preload 类型与 FileService 契约测试；Electron 构建通过。

#### 10. `feat(card): add a filesystem-backed CardDocument repository`

范围：repository 只扫描 `.modstudio/cards/`，支持读取、原子保存和逐 Card 错误隔离；`entities.json` 仅由文档重建，不成为读取前提。

验证：使用真实临时项目目录测试原子写、损坏 JSON、单 Card 隔离、索引重建和中断后不出现半文件。

#### 11. `feat(card): back up and persist known schema migrations`

范围：已知旧 schema 首次写回前备份原文档，再原子替换；备份、转换或写回失败时保留原文并将该 Card 置为只读恢复。

验证：真实临时目录覆盖成功迁移、备份失败、写回失败和其他 Card 不受影响。

#### 12. `feat(card): isolate C# parsing behind explicit legacy import`

范围：

- 正常项目加载只调用 CardDocument repository。
- 只有用户选择“导入旧项目”时才扫描和解析 `scripts/Cards/*.cs`。
- 导入生成带空图和旧产物保护标记的迁移草稿，并逐 Card 报告冲突与未迁移行为。
- `.modstudio/cards/` 已存在后，不再自动回退到 C#。

验证：用调用计数/故障注入证明正常加载从不触碰解析器；显式迁移、重复迁移、ID 冲突和旧 C# 不被覆盖均有真实目录测试。

#### 13. `refactor(card-store): select and mutate cards by immutable ID`

范围：Store 以 Card ID 管理选择、更新和删除；数组索引只用于显示顺序。移除按名称/类型查找身份和把 Card 数据写入 localStorage 的行为。

验证：重命名不丢选择、排序不改身份、大小写冲突拒绝、项目切换不串数据。

#### 14. `feat(project): load CardDocuments when a project opens`

范围：项目切换先 flush 旧项目，再以 repository 结果装载 Store；可编辑 Card、迁移后 Card、只读恢复 Card 和损坏项分别呈现，不让单项错误阻止项目。

验证：项目 A/B 切换、空项目、部分损坏、未来 schema 和加载失败组件测试。

#### 15. `feat(card): require ID confirmation before first persistence`

范围：新建流程从显示名称建议 PascalCase ID，纯中文或冲突时要求用户确认；首次成功落盘后 ID 控件锁定，重命名不改文件名或类名。

验证：建议 ID、手工输入、大小写冲突、首次落盘前修改和落盘后不可变。

### 阶段 D：统一编辑历史与原位 UI

#### 16. `refactor(history): extract generic immutable snapshot history`

范围：把 NodeGraph 已验证的 past/present/future 机制提取成泛型历史核心，保留 no-op 引用约定、100 步裁剪与 redo 分叉规则。

验证：纯函数历史测试；现有 Relic/NodeGraph 历史回归全绿。

#### 17. `feat(card-history): add Card-level edit transactions`

范围：CardEditSnapshot 同时含基本属性和图；支持离散事务、同字段 750ms/blur 合并以及显式 begin/update/commit，不把保存或生成状态放入历史。

验证：输入合并、失焦收束、离散操作、undo/redo、跨 Card 隔离和 AI 单事务占位测试。

#### 18. `feat(canvas): coalesce one node drag into one Card transaction`

范围：NodeGraphCanvas 暴露一次拖动的开始、实时更新和结束边界；Card 历史只记录 pointer-down 前与 pointer-up 后快照。

验证：多帧移动只占一步、取消拖动/no-op 不入栈、原有画布交互不退化。

#### 19. `feat(card-editor): integrate NodeGraph into the existing editor`

范围：在现有 CardEditor 原位加入顶部属性区、Card palette、节点画布、统一 undo/redo 和折叠生成预览；保留现有 Card 列表、筛选、预览和项目上下文。此时用户侧只有一个 CardEditor 入口。

验证：表单与图交替撤销、切换 Card、palette 过滤、连线错误和现有卡牌管理组件测试。

#### 20. `feat(card): autosave drafts and flush lifecycle boundaries`

范围：结构安全变化防抖保存 CardDocument；切换 Card、切换项目、关闭窗口前强制 flush。保存状态与生成状态分开展示，自动保存不生成 C#。

验证：fake timer 防抖、切换 flush、项目切换 flush、关闭握手、写入失败重试且编辑不丢失。

### 阶段 E：确定性生成与产物安全

#### 21. `refactor(codegen): share deterministic linear-chain traversal`

范围：抽取一次确定性的 trigger→线性 effect 收集逻辑供 Card/Relic codegen 消费；Card 方法名读取 registry，不从字符串猜测；遇到未知/空分支立即失败。

验证：多 trigger、链顺序、空分支、未知 kind、转义和 Relic codegen 回归。

#### 22. `feat(card): generate C# from the canonical CardDocument`

范围：Card codegen 与模板只接受权威 CardDocument/已校验语义；类名和文件名只来自不可变 Card ID。生成按钮先 flush 草稿，再做生成校验，再在内存生成。

验证：表单字段、四种 Card trigger、Self/Owner effect、多个方法、非法草稿不产生写盘调用。

#### 23. `feat(card): compute semantic and generator fingerprints`

范围：规范化只影响 C# 的字段、kind、参数和链顺序后计算 sourceHash；排除坐标、时间戳与 UI 状态；generatorVersion 覆盖模板和 emit/codegen 内容。

验证：移动节点哈希不变，改语义哈希变化，模板/emit 版本变化使生成器过期，序列化顺序稳定。

#### 24. `feat(card): atomically write and verify generated artifacts`

范围：原子写入 C#，重新读取磁盘内容计算 artifactHash，成功后才更新 CardDocument 指纹。生成失败保留已保存草稿与上次有效 C#，并标记未同步。

验证：写失败、读回失败、指纹文档写失败和成功路径的真实目录测试。

#### 25. `feat(card): protect externally modified C# artifacts`

范围：打开项目、重新生成和测试预检时比较 artifactHash；不一致时禁止无提示覆盖，提供备份/导出后重新生成，不提供反向合并。

验证：外部修改检测、备份成功/失败、确认重生成和解析器零调用测试。

### 阶段 F：删除、批量操作与测试预检

#### 26. `feat(card): move deleted cards to project trash atomically`

范围：删除先 flush，再完整暂存 Card 文档与现有 C#，校验后移除活动文件；任一步失败执行补偿，只有活动 C# 确认不存在才从 Store 移除。

验证：每个故障点的真实目录注入测试；失败后 Card 仍活跃且文件组合恢复。

#### 27. `feat(card): restore cards from trash with ID conflict checks`

范围：列出和恢复回收站 Card，恢复前按忽略大小写规则检查活动 ID；冲突不自动改名。永久删除保持独立显式确认。

验证：有/无产物恢复、冲突、部分恢复失败与回收站保留测试。

#### 28. `feat(card): add best-effort batch generation reports`

范围：逐 Card 生成；可生成项独立更新指纹，草稿和只读项记为跳过，失败不终止批次，最终展示成功/跳过/失败原因。

验证：混合状态顺序、单项故障隔离、报告计数和每张成功立即持久化。

#### 29. `feat(test): gate game launch with artifact preflight`

范围：启动前列出实际加载的 Card；未生成草稿可排除，缺失/写入失败/生成器过期/外部修改阻止；草稿新于旧有效 C# 时允许本次明确选择测试上次生成版本。预检不隐式生成。

验证：状态矩阵组件测试与 launch 调用次数断言。

### 阶段 G：AI 提案与最终收口

#### 30. `feat(ai): request and validate complete Card proposals`

范围：AI 结构化输出覆盖完整 Card 草稿与行为图，经过与磁盘导入相同的结构/registry seam；响应先成为预览提案，不直接写 Store。

验证：合法提案、schema 违规、未知 kind、provider 错误和当前 Card 不变。

#### 31. `feat(ai): apply revision-bound proposals as one transaction`

范围：请求记录 Card revision；提案预览属性、节点和连线差异；只有基线未变化时可确认，确认应用为一个 Card 历史事务并触发自动保存但不生成。过期提案只读并提供重新生成。

验证：确认/取消、单步撤销、请求期间继续编辑、过期禁止应用和重新生成。

#### 32. `refactor(card): remove superseded dual paths`

范围：在已吸收试作功能并通过测试后，删除第二份 CardData、平行 CardEditor、重复 BFS/codegen/template；旧 C# parser 只保留在 legacy-import 模块的依赖图内，正常 load/save 模块不得 import 它。

验证：静态依赖测试/搜索证明只有一个 CardData、一个 CardEditor 入口、一个 Card codegen；正常加载解析器零调用；全套测试与构建通过。

#### 33. `test(card): exercise the v0.9 release gate end to end`

范围：补齐真实临时目录端到端测试和 Electron 手工 smoke 清单；验证新建→编辑→自动保存→重启恢复→生成→预检，以及迁移、外部修改、删除/恢复。更新版本与用户文档。

验证：完整测试、TypeScript、Vite/Electron 构建全绿；按 ADR-0006 手工 smoke 清单签收。

## 5. 每阶段合并门槛

| 阶段 | 必须保持成立的系统性质 |
|---|---|
| A | 只有一个 Card 模型；v0.9 kind 范围明确 |
| B | 草稿可保存，非法语义不可生成 |
| C | 正常加载只读 `.modstudio`；C# 解析只在显式迁移中可达 |
| D | 用户仍使用原 Card 编辑入口；表单与图共享历史和保存 |
| E | 生成确定、可恢复，且不会静默覆盖外部 C# |
| F | 删除、批量生成和游戏启动不会制造或掩盖半完成状态 |
| G | AI 不直接覆盖草稿；仓库无双轨残留；发布门禁闭环 |

阶段 C 是最重要的架构检查点：若正常加载路径仍 import 或调用 C# parser，不进入阶段 D。

## 6. 测试策略

### 单元测试

- Card ID、CardDocument parser、schema migrations。
- 图结构校验、Card 生成校验、线性链遍历。
- 泛型历史、Card 编辑事务、语义哈希和同步状态分类。
- AI proposal revision 与批量生成/预检决策矩阵。

### 组件测试

- 原位 CardEditor 的列表、选择、表单、画布、历史和状态反馈。
- 创建 ID、迁移报告、只读恢复、回收站、批量报告和测试预检交互。
- AI 差异预览、确认、过期和重新生成。

### 真实文件集成测试

使用每个测试独立的临时项目目录，不 mock 文件结果，覆盖：

- CardDocument 原子写与项目重开。
- schema 备份迁移和单 Card 隔离。
- 一次性旧 C# 导入与旧产物保护。
- 生成写入/读回指纹、外部修改、删除补偿和恢复冲突。

### Electron smoke test

- 关闭窗口前 flush。
- preload/main 文件能力在真实应用中可用。
- 打开/切换项目、生成、删除/恢复和启动预检完整走通。

## 7. 明确不在 v0.9 范围

- Relic Any trigger 与 EventTarget effect。
- 条件、分支、循环或共享动作组节点。
- 从已生成 C# 持续同步或反向合并编辑。
- AI 提案的逐字段/逐节点采纳与自动三方合并。
- 真实 LLM provider 作为发布阻塞项。
- 真实游戏内行为和三平台安装包全量验证。
- Steam Workshop 发布流程。

## 8. 完成定义

只有同时满足以下条件，v0.9 才算完成：

1. 正常打开项目只从 `.modstudio/cards/` 恢复 Card。
2. 旧 C# 导入必须由用户显式启动，成功后不会再次自动运行。
3. 仓库只有一份权威 CardData 和一个 CardEditor 入口。
4. Card 属性与行为图能够自动保存、重启恢复、统一撤销和显式生成。
5. 生成、删除、外部修改、批量生成和游戏预检都符合 ADR 中的数据安全语义。
6. AI 提案可预览、可单步撤销、会因 revision 变化而过期。
7. 自动化门禁全绿，Electron smoke 清单完成。
